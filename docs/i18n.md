# Translations (i18n)

Clay's built-in component text — table toolbars, pickers, dialogs, the app shell, map and chart
controls, toasts — is translatable, and the dates and numbers Clay formats follow the active locale.
English is the default; Clay ships a complete **European Portuguese (`pt-PT`)** catalog.

- [Setup](#setup): `ui.run({ locale })`
- [Per-session locale](#per-session-locale): `ui.setLocale`, browser language
- [Overriding messages](#overriding-messages): `ui.run({ messages })`

- [Formatting](#formatting): dates, numbers, relative time
- [Adding a language](#adding-a-language)
- [How it works](#how-it-works)

## Setup

```typescript
ui.run({
  locale: 'pt-PT', // default UI language for every session
});
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `locale` | `string` | `'en'` | BCP 47 tag (`'pt-PT'`, `'en'`). `'auto'` picks the best match for the browser's languages among available catalogs (`pt-BR` → `pt-PT`, `en-GB` → `en`), else English. |
| `messages` | `{ [locale]: { [key]: string } }` | | Override or add messages per locale. See [Overriding messages](#overriding-messages). |

With `locale: 'pt-PT'` every Clay component renders in Portuguese: `ui.dataTable` shows
"Pesquisar...", "Filtrar", "Exportar", "Recolher tudo", "Linhas por página", "Sem resultados";
`ui.timeline` shows "Mostrar detalhes"; date pickers show Portuguese month and weekday names with
weeks starting on Monday; charts, stats and tables format `1234,5`-style numbers. `<html lang>` is set
to match.

With the `clay` CLI and a page directory, set it in `_run.ts`:
`export function configureRun(base) { return { ...base, locale: 'pt-PT' }; }` (see [Boot](./boot.md)).

Text you pass yourself (`ui.button('Save')`, column headers, `placeholder`, `emptyText`, …) is used
as-is: a prop you set always wins over Clay's translated default.

## Per-session locale

```typescript
ui.dropdownMenu({ label: 'Idioma', variant: 'ghost' }, () => {
  ui.menuItem('Português', { onClick: () => ui.setLocale('pt-PT') });
  ui.menuItem('English', { onClick: () => ui.setLocale('en') });
});
```

| Call | Returns | Description |
|------|---------|-------------|
| `ui.setLocale(locale, opts?)` | `void` | Switch this tab's language. The browser remembers it (`localStorage` `clay-locale`) and reports it on reconnect, so it survives reloads. `null` clears the choice (back to the app default). |
| `ui.getLocale()` | `string` | The session locale (else the `ui.run` default). |
| `ui.i18n.availableLocales()` | `string[]` | Locales with a catalog (built-in + `messages`). |
| `ui.i18n.getDefaultLocale()` | `string` | The `ui.run({ locale })` default. |

Switching is live, without a browser reload. Clay's own component text re-renders in place. By
default (`{ remount: true }`) the current page is also rebuilt on the server so text your page
code produced with `ui.t` / `ui.messages` follows; pass `{ remount: false }` to keep page state
when your page has no translated strings of its own.

Order of precedence for a session: the user's stored choice (`ui.setLocale`) → the browser's
languages when `locale: 'auto'` → the `ui.run({ locale })` default → English.

## Overriding messages

Every built-in string has a key (`dataTable.export`, `timeline.showDetails`, `common.cancel`, …).
Override any of them per locale:

```typescript
ui.run({
  locale: 'pt-PT',
  messages: {
    'pt-PT': { 'dataTable.export': 'Descarregar' },
    en: { 'dataTable.export': 'Download' },
  },
});
```

A key missing from a locale falls back to the same language's other catalog (`pt-BR` → `pt-PT`)
and then to English — never to the raw key. The full key list, with English and Portuguese text,
lives in `@close-by/clay-core` under `src/i18n/messages/*.ts`; at runtime `CLAY_CATALOGS.en` (from
`@close-by/clay-core`) has every key, and the `ClayMessageKey` type autocompletes them.

Server code can read a built-in message in the session locale with `ui.t(key, params?)`, e.g.
`ui.t('common.cancel')` → `'Cancelar'`.

## Your app's own strings

`ui.messages` gives your app a small typed dictionary with the same locale and fallback rules:

```typescript
const t = ui.messages({
  en: {
    title: 'Orders',
    greeting: 'Hello, {name}',
    orders_one: '{count} order',
    orders_other: '{count} orders',
  },
  'pt-PT': {
    title: 'Encomendas',
    greeting: 'Olá, {name}',
    orders_one: '{count} encomenda',
    orders_other: '{count} encomendas',
  },
});

ui.page('/orders', () => {
  ui.pageHeading(t('title'));
  ui.label(t('greeting', { name: user.name }));
  ui.label(t('orders', { count: rows.length })); // '3 encomendas'
});
```

- `en` is required and defines the keys; other locales may be partial (missing keys fall back to
  English). Keys are type-checked: `t('titel')` is a compile error.
- `{name}` placeholders are replaced from `params`; numbers are formatted for the locale.
- Plurals: when `params.count` is a number, `key_one` / `key_other` (any `Intl.PluralRules`
  category: `zero`, `one`, `two`, `few`, `many`, `other`) are tried before `key`.
- `t.in('en', 'title')` translates for an explicit locale (emails, exports).
- Call `t(...)` while the page builds (or in handlers): it reads the current session's locale.
  Build-time text follows `ui.setLocale` because the page is rebuilt (`remount`, the default).

Keep dictionaries in a module (`messages.ts`) and import `t` where needed.

## Formatting

Clay formats with the session locale wherever it formats values itself: date pickers and the
calendar (month/weekday names, first day of week), `ui.relativeTime`, chart axes and tooltips,
`ui.stat` values, data table number/date/currency columns, gantt and event calendar headers.

For text you build on the server, the same helpers are available:

| Call | Example (`pt-PT`) |
|------|-------------------|
| `ui.formatNumber(1234.5)` | `1234,5` |
| `ui.formatNumber(0.25, { style: 'percent' })` | `25%` |
| `ui.formatNumber(12345.5)` | `12 345,5` |
| `ui.formatNumber(9.9, { style: 'currency', currency: 'EUR' })` | `9,90 €` |
| `ui.formatDate(new Date())` | `27/11/2026` (`{ dateStyle: 'medium' }`) |
| `ui.formatDate(d, { dateStyle: 'long' })` | `27 de novembro de 2026` |
| `ui.formatRelativeTime(d)` | `há 5 minutos`, `ontem` |

They are thin wrappers over `Intl.NumberFormat`, `Intl.DateTimeFormat` and
`Intl.RelativeTimeFormat` with the session locale. Server time zone rules apply on the server;
pass `{ timeZone: 'Europe/Lisbon' }` when it matters.

Week start comes from `Intl.Locale#getWeekInfo` (CLDR), except that Portugal is set to Monday (CLDR
lists Sunday, but Portuguese calendars follow ISO 8601).

## Adding a language

For one app, pass a full catalog under a new locale key. Keys you leave out stay English:

```typescript
import { CLAY_CATALOGS } from '@close-by/clay-core';

const es = { 'common.cancel': 'Cancelar', 'dataTable.export': 'Exportar', /* … */ };

ui.run({ locale: 'auto', messages: { es } });
```

`ui.i18n.availableLocales()` then includes `es`, `locale: 'auto'` matches Spanish browsers to it,
and `ui.setLocale('es')` works. Use `Object.keys(CLAY_CATALOGS.en)` as the checklist. Dates and
numbers need no catalog: `Intl` already knows every locale.

To ship a language with Clay itself, add it next to `ptPT` in each
`packages/core/src/i18n/messages/*.ts` file and register it in `packages/core/src/i18n/catalog.ts`;
the catalog tests check every English key is translated and placeholders match.

## How it works

- Catalogs and the lookup/format helpers are plain TypeScript in `@close-by/clay-core`
  (`src/i18n/`), shared by the server and the React client bundle.
- `ui.run` embeds the default locale, the available locales and your `messages` overrides for
  Clay keys in the page (`window.__CLAY_I18N__`), so the first render is already translated.
- On connect the client reports its stored choice and `navigator.languages`; the server resolves
  the session locale with the same rules (see `ui.getLocale()`).
- `ui.setLocale` sends a `locale` message; the client stores it, re-renders Clay text in place and,
  with `remount`, asks the server to rebuild the page. See [WebSocket protocol](./protocol.md).
